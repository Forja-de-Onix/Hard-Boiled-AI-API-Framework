# Base de Datos

Hard Boiled resuelve tu conexión a base de datos automáticamente según
`DB_ENGINE` en `.env` — lo configuras una vez y nunca tocas
`hardboiled/database.py` directamente.

## Motores soportados

| `DB_ENGINE` | Driver | ¿Async? |
|---|---|---|
| `postgres` | SQLAlchemy + `asyncpg` | Sí |
| `mysql` | SQLAlchemy + `aiomysql` | Sí |
| `mongo` | Motor (driver oficial async de MongoDB) | Sí |

No se usó Mongoengine para la parte de MongoDB a propósito: es una librería
síncrona, y usarla dentro de un núcleo `asyncio` bloquearía el event loop o
exigiría envolver cada llamada en `run_in_executor`. Motor está construido
para `asyncio` desde su base, así que encaja con la filosofía del núcleo del
framework.

## Configurar `.env`

Consulta [Setup](Setup.md) para ver todas las variables (`DB_HOST`, `DB_PORT`,
`DB_NAME`, `DB_USER`, `DB_PASSWORD` para SQL, o `MONGO_URI` para Mongo).

## Inicializar al arrancar

Llama a `init_database()` una vez, antes de `app.listen(...)`:

```python
from hardboiled.database import init_database

init_database()
```

## Uso — SQL (Postgres/MySQL)

```python
from hardboiled.database import get_session

async def list_users(req, res):
    async with get_session() as session:
        # consulta usando la sesión async de SQLAlchemy
        pass
    res.json({"users": []})
```

`get_base()` devuelve el `Base` declarativo compartido para definir modelos:

```python
from hardboiled.database import get_base

Base = get_base()

class User(Base):
    __tablename__ = "users"
    # ...
```

## Uso — MongoDB

```python
from hardboiled.database import get_mongo_db

async def list_users(req, res):
    db = get_mongo_db()
    users = await db["users"].find().to_list(length=100)
    res.json({"users": users})
```

## Errores

`get_engine()`, `get_session()`, `get_base()` y `get_mongo_db()` lanzan un
`RuntimeError` claro si se llaman antes de `init_database()` — nunca
devuelven `None` en silencio.
