# Scaffold

Hard Boiled marca una línea clara entre el **núcleo del framework** y la **capa de la app**.

## `hardboiled/` — núcleo del framework

```
hardboiled/
├── init.py
├── app.py # Clase App, servidor asyncio, ciclo de vida del request
├── router.py # Resolución de rutas, parámetros de ruta
├── connectors.py # Interfaz unificada de proveedores de IA (Ollama/Claude/Gemini/ChatGPT)
└── database.py # Resolución de DB_ENGINE (SQLAlchemy / Mongoengine/Motor)
```

Por lo general no modificas estos archivos. Leen la configuración del `.env` y exponen una API estable al resto de tu proyecto.

## Raíz del proyecto — capa de la app


Por lo general no modificas estos archivos. Leen la configuración del `.env` y exponen una API estable al resto de tu proyecto.

## Raíz del proyecto — capa de la app

```
controllers/ # Lógica de negocio por recurso
routes/ # Definición de rutas, conectadas a los controllers
models/ # Modelos de datos, respaldados por lo que resuelva hardboiled/database.py
middlewares/ # Auth, manejo de errores — reemplazables por proyecto
```


Estos son tuyos: los editas, reemplazas o extiendes libremente — son un scaffold de partida generado, no partes internas del framework.

## ¿Por qué esta separación?

Es similar a cómo los frameworks estilo `node_modules` separan los paquetes instalados del código de la aplicación, sin requerir todavía un paso de instalación real — el scaffold simplemente hace explícito el límite desde el día uno, para que quede claro qué es seguro modificar.
