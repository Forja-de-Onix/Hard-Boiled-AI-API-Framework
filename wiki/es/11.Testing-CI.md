# Testing y CI

## pytest

```bash
pip install -r requirements-dev.txt
pytest
```

`pytest.ini` establece `asyncio_mode = auto`, así que las funciones
`async def test_...` corren sin decorar cada una con `@pytest.mark.asyncio`
— necesario porque prácticamente todo en Hard Boiled es async.

Los archivos de test van en `tests/`, siguiendo el nombrado `test_*.py`.
Consulta [Inicio Rápido](06.Inicio-Rapido.md) para ejemplos resueltos.

## GitHub Actions

Un workflow mínimo (`.github/workflows/tests.yml`) instala dependencias y
corre pytest en cada push y pull request. Deliberadamente **no** incluye
pasos de despliegue — eso es específico de cada infraestructura de hosting
y queda fuera del alcance del framework.

```yaml
name: Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
      - run: pip install -r requirements-dev.txt
      - run: pytest
```

Si tus tests tocan la base de datos o un conector de IA, añade el paso de
instalación correspondiente (p. ej. `pip install sqlalchemy[asyncio] asyncpg`
o `pip install httpx`) antes del paso `pytest`.
