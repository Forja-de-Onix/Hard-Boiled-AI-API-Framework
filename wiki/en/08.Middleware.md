# Middleware

Middleware in Hard Boiled follows the Express pattern: a function receiving
`(req, res, next)`, which must call `await next()` to continue the chain.

## Global middleware — `app.use()`

Runs on every request, before route resolution's handler executes:

```python
async def logger_middleware(req, res, next):
    print(f"{req.method} {req.path}")
    await next()

app.use(logger_middleware)
```

## Per-route middleware

Passed directly to the route, and only runs for that route — see
[Routing](07.Routing.md):

```python
@app.get("/me", middlewares=[jwt_auth_middleware])
async def me(req, res):
    ...
```

## Execution order

Route-level middlewares run closer to the handler than global ones. For a
request to a route with its own middleware:

```
global middleware 1 → global middleware 2 → route middleware → handler
```


## Short-circuiting

A middleware can stop the chain by simply not calling `next()` — commonly
after setting an error response:

```python
async def jwt_auth_middleware(req, res, next):
    auth_header = req.headers.get("authorization", "")
    if not auth_header.startswith("Bearer "):
        res.status(401).json({"error": "Missing Bearer token"})
        return  # next() is never called — the handler never runs

    await next()
```

## Error handling

Any exception raised inside a handler or a middleware is caught at the
dispatch level and turned into a `500` with the exception message — there's
no need to wrap every handler in `try/except` yourself. If you want custom
error formatting, write your own error-handling middleware and place it
first in `app.use(...)`, wrapping `await next()` in your own `try/except`.
