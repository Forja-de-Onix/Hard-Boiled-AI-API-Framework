# Scaffold

Hard Boiled draws a hard line between **framework core** and **app layer**.

## `hardboiled/` — framework core

```
hardboiled/
├── init.py
├── app.py # App class, asyncio server, request lifecycle
├── router.py # Route matching, path params
├── connectors.py # Unified AI provider interface (Ollama/Claude/Gemini/ChatGPT)
└── database.py # DB_ENGINE resolution (SQLAlchemy / Mongoengine/Motor)
```

You generally don't modify these files. They read configuration from `.env` and expose a stable API to the rest of your project.

## Project root — app layer

```
controllers/ # Business logic per resource
routes/ # Route definitions, wired to controllers
models/ # Data models, backed by whatever hardboiled/database.py resolves
middlewares/ # Auth, error handling — replaceable per project
```

These are yours to edit, replace, or extend freely — they're generated as a starting scaffold, not framework internals.

## Why this split?

It mirrors how `node_modules`-style frameworks separate installed packages from application code, without actually requiring a package install step yet — the scaffold just makes the boundary explicit from day one, so it's obvious what's safe to modify.
