# Database

Hard Boiled resolves your database connection automatically based on
`DB_ENGINE` in `.env` — you configure it once and never touch
`hardboiled/database.py` directly.

## Supported engines

| `DB_ENGINE` | Driver | Async? |
|---|---|---|
| `postgres` | SQLAlchemy + `asyncpg` | Yes |
| `mysql` | SQLAlchemy + `aiomysql` | Yes |
| `mongo` | Motor (official async MongoDB driver) | Yes |

Mongoengine was deliberately not used for the MongoDB path: it's a
synchronous library, and using it inside an `asyncio` core would either block
the event loop or require wrapping every call in `run_in_executor`. Motor is
built for `asyncio` from the ground up, so it fits the framework's core
philosophy.

## Configuring `.env`

See [Setup](Setup.md) for the full variable list (`DB_HOST`, `DB_PORT`,
`DB_NAME`, `DB_USER`, `DB_PASSWORD` for SQL, or `MONGO_URI` for Mongo).

## Initializing at startup

Call `init_database()` once, before `app.listen(...)`:

```python
from hardboiled.database import init_database

init_database()
```

## Using it — SQL (Postgres/MySQL)

```python
from hardboiled.database import get_session

async def list_users(req, res):
    async with get_session() as session:
        # query using SQLAlchemy's async session
        pass
    res.json({"users": []})
```

`get_base()` returns the shared declarative `Base` for defining models:

```python
from hardboiled.database import get_base

Base = get_base()

class User(Base):
    __tablename__ = "users"
    # ...
```

## Using it — MongoDB

```python
from hardboiled.database import get_mongo_db

async def list_users(req, res):
    db = get_mongo_db()
    users = await db["users"].find().to_list(length=100)
    res.json({"users": users})
```

## Errors

`get_engine()`, `get_session()`, `get_base()`, and `get_mongo_db()` all raise
a clear `RuntimeError` if called before `init_database()` — there's no silent
`None` returned.
