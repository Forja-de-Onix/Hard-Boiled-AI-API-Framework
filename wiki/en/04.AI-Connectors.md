# AI & Connectors

Hard Boiled talks to AI providers through a single unified interface, so your
app code never needs to know which provider is active — only `.env` decides
that.

## Architecture

```
hardboiled/
├── connectors.py # Provider-specific classes (Ollama, Claude, Gemini, ChatGPT)
└── ai_response.py # Provider-agnostic ask() function used by your app
```


- **`connectors.py`** — each provider is a class inheriting from `AIConnector`,
  which defines the common interface (`chat`, `chat_stream`) and pulls its own
  configuration (API keys, host, default model) from environment variables set
  in `.env`. This file is framework core — you generally don't edit it.
- **`ai_response.py`** — a thin layer that resolves the active connector via
  `get_connector()` and exposes a single `ask()` function. It knows nothing
  about HTTP or about any specific provider; it only decides *whether* to
  stream, based on `STREAM_DEFAULT` (or an explicit override).

## Choosing a provider

Set `AI_CONNECTOR` in `.env` to `ollama`, `claude`, `gemini`, or `chatgpt`. See
[Setup](Setup.md) for the full list of variables each provider needs.

## Using `ask()` in your own code

```python
from hardboiled.ai_response import ask

# Non-streaming: returns a string
answer = await ask("What's the capital of France?", stream=False)

# Streaming: returns an async generator of text chunks
stream = await ask("Write me a long story", stream=True)
async for piece in stream:
    print(piece, end="", flush=True)
```

`stream=None` (the default) falls back to `STREAM_DEFAULT` from `.env`.

## Wiring it to an HTTP endpoint

`res.stream(...)` accepts any async generator and serves it as chunked HTTP:

```python
from hardboiled.ai_response import ask

@app.post("/ask")
async def ask_endpoint(req, res):
    body = req.json()
    result = await ask(body["prompt"], model=body.get("model"), stream=body.get("stream"))

    if hasattr(result, "__aiter__"):
        res.stream(result)
    else:
        res.json({"response": result})
```

## Trying it with curl

Streaming responses use chunked transfer encoding, and by default `curl`
buffers output in some conditions before printing it. To see the response
arrive progressively, always use `-N` (or `--no-buffer`):

```bash
curl -N -X POST http://localhost:3000/ask \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Cuéntame una historia larga sobre un cuervo y un zorro"}'
```

Without `-N`, the request still streams correctly at the network level — you
just won't *see* it arrive progressively in your terminal, since curl
withholds the output until the response finishes.

To force a non-streaming response instead (a single JSON object):

```bash
curl -X POST http://localhost:3000/ask \
  -H "Content-Type: application/json" \
  -d '{"prompt": "hola", "stream": false}'
```

## Adding a new provider

1. Add a class in `connectors.py` inheriting from `AIConnector`, implementing
   `_get_default_model`, `chat`, and `chat_stream`.
2. Register it in the `_CONNECTORS` dict.
3. Document its required `.env` variables in [Setup](Setup.md).

`ai_response.py` requires no changes — it only depends on the common
`AIConnector` interface.
